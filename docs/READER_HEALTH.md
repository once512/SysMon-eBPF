# 权限读取者进度监督（2026-10-26）

fanotify静态和分析模式均每约250ms排队一个进度探测；同一时间最多一个未确认探测。读取者只有回到命令循环并处理完前序命令，才能回复匹配序号的确认；只检查进程存在不能替代它。探测不打开文件、不进入pending、不消耗分析请求号、不产生权限审计。

管理状态提供：

| 字段 | 含义 |
| --- | --- |
| reader_pid | 本实例当前读取子进程的PID，仅用于诊断 |
| reader_state | responsive：最近确认距今小于2000ms；unresponsive：已达到2000ms |
| reader_progress_age_ms | 主事件循环收到最近匹配确认后经过的单调毫秒数；初值来自Ready握手 |

查询仅计算已有时间戳的年龄，不同步探测、取路径属性或等待子进程。响应迟缓可能来自VFS等待、IPC拥堵、进程被停止或调度延迟；不是已经确认文件系统故障。responsive也不是瞬时活性保证。管理协议升级为同包v9/472字节；拒绝旧布局，主服务和客户端需一起构建。BPF和分析器ABI未因此改变。

控制消息与事件回复共享单调帧序号；事件、派发失败和进度确认分别验证。接收先peek正文，只有实际事件才预留eventfd，避免心跳在无空闲FD时额外消耗裁决句柄。命令队列固定4099项（最多4097清理、一个分析派发、一个探测），没有按时间无限堆积探测。

读取者卡住时不自动退出、不重建group、不丢弃已交付队列；已有期限继续生效，恢复后同一读取者可继续。读取者真正断连仍是既有致命后端错误，服务退出并释放资源；没有新增自动重启、端到端系统调用期限或持久防护。未知/未交付的等待不能伪造逐请求拒绝审计。不可中断D状态及同group队首阻塞仍见[读取合同](STATIC_EVENT_READER.md)和[分析路径](ANALYSIS_EVENT_READER.md)。

验证专题`reader-health`覆盖空闲超过两秒仍有进度、SIGSTOP后退化、未交付请求不误计pending/审计、SIGCONT恢复、再次停止期间授权退出及读取者死亡报告，交叉静态/分析和legacy/pidfd。SIGSTOP故障注入使用独立fanotify诊断实例，不取消联合服务自保护。
