# 特权辅助进程自保护（2026-10-26）

权限读取者持有fanotify group，不能只保护主进程而忽略读取者。启用BPF自保护时，原有TASK_STORAGE绑定主服务的实际task；LSM现在也检查目标线程组的实际real_parent：若它的父线程组有该绑定，且目标real/effective UID均为初始user namespace的0，则按特权直接子进程保护。

拒绝外部信号（信号0除外）、ptrace及经过该ptrace检查的进程访问。允许目标线程组自身，以及绑定的父服务线程组执行操作，因此管理停止、准备超时清理和目标切换不需要临时解除保护。比较的是实际task指针和task-local绑定，不维护可复用PID白名单；新读取者创建后自动适用父任务规则，无需另行登记。读取者另设置不可dump，减少未启用BPF时的进程检查暴露；这不能代替LSM保护。

范围限定为特权直接子进程，不递归授权子孙，不授予兄弟进程管理权限。降权到65534的扫描器不属于该root辅助规则，其已有后端错误/超时回退保持不变。测试故障扫描器也降权后再发Ready，以便在联合实例中注入故障而不关闭辅助保护。独立启动的FUSE提供进程不是主服务子进程，本轮没有把它纳入自保护或自动恢复。

自保护只有在原有BPF自保护已启用且钩子仍挂载时有效；fanotify-only诊断模式不提供该LSM保护。启动安装窗口、内核生成的终止、完整管理员权限、主服务死亡后持久保护等边界并未解决。管理socket仍按原有root授权合同，不是对完整系统管理员的隔离。

`helper-protection`专题验证静态/分析模式的信号、pidfd信号、ptrace及/proc内存拒绝，核对self_denied审计；验证新旧读取者切换、父服务清理、无关进程不受影响及降权扫描器的既有行为。另在独立PID/mount namespace重跑，确认父任务保护不依赖用户态PID坐标；审计target_pid仍沿用已有内核坐标，不伪装成namespace内PID。
