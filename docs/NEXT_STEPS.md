## 本轮已收紧诊断 I/O 边界

服务期 stderr（含 libbpf 日志）现在使用独立有界队列：256 条、256 KiB、每行最多 4096 字节，FIFO 满时丢弃新行，超长行整行丢弃。所有后端的 status 提供 diagnostic_* 计数；stdout 审计与 stderr 的预算、线程和错误状态互相独立。

已经验证启动前填满 stderr、失败重载洪流、周期报告、恢复/断开、状态查询及不排空管道的授权退出。普通文件底层存储卡住仍可能影响输出线程 join；fanotify-only 的最终 stdout 统计仍是权限组关闭后的同步输出。具体契约见 [审计/诊断出口](AUDIT_OUTPUT.md)。

## 本轮已补齐逐请求裁决审计

--audit-permissions 在成功写回权限回复后输出 fanotify_decision，保留接收时的原始 PID、对象身份、revision、请求号和单调时钟；静态/扫描裁决、容量、超时、分析错误和正常停止拒绝都覆盖。忙时或准备失败的重载不会改写旧请求版本。对象身份从固定目标缓存，不为审计增加逐请求路径解析或 /proc 查询。

BPF 和 fanotify 借用服务拥有的唯一 stdout 队列；开启权限审计时，fanotify-only 的 stdout 也是 JSONL，结束统计写 stderr。共享预算没有按种类预留，日志丢失仍需通过 audit_* 及内核统计观察。字段与实际边界见 [逐请求裁决审计](PERMISSION_AUDIT.md)。

## 下一步：进程生命周期键上的行为规则及误报验证

2026-10-20 已加入[覆盖评估器](BEHAVIOR_EVALUATION.md)，分别计量输入证据缺失与有界状态漏匹配。新增同进程 96 次连续操作和 GNU sed 正常保存反例，40 个真实采集变体及 3360 组评估配置通过；权限集中后到时，历史容量 32 漏匹配 64 次，128 则无漏匹配。这是给定输入上的模式覆盖结果，真实攻击样本、部署场景误报率和响应闭环仍待完成。

随后加入[八类应用与受控破坏场景](BEHAVIOR_APPLICATIONS.md)：普通文件保存、GNU sed、SQLite、日志改名，以及读取后覆盖、截断、分进程和延迟写入。[32 个正式变体及 1344 组回放配置通过](VALIDATION_APPLICATIONS_2026_10_20.md)。场景揭示正常保存与读取后覆盖可命中同一模式；截断、分进程与超过窗口的修改仍被原生保护拒绝，但不会命中该模式。下一步应先选择具体部署应用及独立恶意判据，补齐更长行为链；仅扩大窗口或跨 PID 拼接不能解决意图区分。

新增[进程内多对象汇总](OBJECT_CHAINS.md)，区分多对象修改拒绝与具备访问证据的多对象时间配对。[四个八对象/七进程变体及 76 包回放验证通过](VALIDATION_CHAINS_2026_10_20.md)。重复修改同一文件不会增加不同对象数；正常批量保存与受控覆盖仍无法仅凭对象范围区分。已明确当前 fanotify 每实例仅标记一个固定文件，下一轮优先设计多目标订阅及预算、请求对象身份、重载与失败回滚，再扩展多文件访问链验收。

后续已实现[固定多目标订阅](FANOTIFY_MULTITARGET.md)：同一 group 最多 64 个普通文件，共享 pending/分析预算，每个请求保存自身对象快照。目标集合变更仍要求重启，裁决重载和准备失败保留旧配置；配置加载排除全部订阅目标，避免次要目标硬链接导致自我等待。管理 ABI 更新为 v4/360 字节并报告 fanotify_targets。[完整 44 项特权回归及 64 目标持续验证通过](VALIDATION_MULTITARGET_2026_10_20.md)：55 轮、220 个变体、70400 次修改拒绝，全部采集包可精确重放。下一步继续按部署场景建立正常应用基线及独立恶意判据；完整多对象配对仍不足以区分正常批量保存与破坏意图。

本轮在此基础上加入[即时静态 allow 模式在线目标切换](FANOTIFY_HANDOVER.md)：共同路径保留旧 inode，新增目标独立准备，失败保留旧 group，成功后请求号及累计统计连续。已通过 45 项特权回归，另用积压请求实验明确旧内核未读请求按先前 allow 释放、不能补造逐请求审计的边界。拒绝、延迟和扫描模式的目标变更仍需重启；任意拒绝策略无损迁移需要独立解决旧在途事件合同，不能把清空 mark 当作用户态同步屏障。

## 补齐授权的信任与会话语义

执行 inode/EUID 匹配没有认证动态库、插件、解释器承载代码、环境和运行时完整性。当前 UID 是内核全局坐标；容器内 UID、程序部署和可信发布边界仍应单独设计。

研究内容/加载链认证时，先确定信任根、升级/回滚和撤销流程，再选择现成机制，避免自行发明签名体系。保险箱现已具备 root 管理的指定文件读授权、独立期限、临时解锁及锁定合同；下一步收敛最终用户授权、真实应用保存方式和恢复体验。现有共享可写映射、已复制内容和在途 I/O 不能靠删除一条 Map 规则追回。会话验收应明确哪些新访问被拒绝、已有能力如何处理。

## 建立可验证的行为与响应闭环

凭证基线异常目前属于审计线索，合成不一致测试不是已识别真实提权攻击。分析器的 BLOCK 字节规则也是实验机制。临时真实诱饵及受控证据关联已有实验；通用可信关联、误报控制、确认后的拒绝/隔离和恢复流程尚未完成。

临时真实诱饵已验证对象、操作、时间和原因，并加入完整文件备份/索引对照。fanotify 已提供逐请求裁决、原因与 namespace 坐标，下一步使用已验证的可选进程键评估跨事件规则、误报与持有引用期间的响应，不能将现有记录直接当作已确认攻击。响应优先更新拒绝规则，再考虑受控进程/cgroup 隔离；停止进程不能回滚此前写入。

## 按明确环境扩展覆盖

已有普通 FD、硬链接/重命名、部分 mmap/mprotect、私有 bind/tmpfs 和 PID namespace 专题。真实内核权限队列溢出、更多异步 I/O/文件系统专用路径、overlay/NFS/FUSE、完整容器和真实 PID 复用仍未据此认定覆盖。

一次只扩展一类入口或环境，保留独立实例、失败回滚和资源回收证据；不要为暂未确定的部署环境先增加历史协议/配置兼容层。资源对象继续按职责组合，内核侧保留 C/Map 模型，避免为了类数量而建立继承树。

## 限时维护写例外（2026-10-21）

新增可选 writer-lease-ms，将当前所有程序写例外限定为内核启动时钟上的期限；同进程旧 FD 到期拒绝与暂停用户态服务仍到期的专题已通过。成功的新 BPF 策略激活会重新计时，失败或同版本不会续期。该机制推进临时写维护场景，但还没有读授权、独立主体会话、可信代码链、加密与既有映射撤销，不能据此称为完整保险箱。


## 凭证观察覆盖（2026-10-21）

已将基线和执行事件扩展为完整 UID/GID、五类 capabilities 及 user namespace 观察，并用真实 setuid/setgid/file-capability/子 user namespace 和 14 个单字段合成偏差验收。仍需定义可信转换来源、敏感点和真实攻击判据；这些字段本身不会使正常 commit_creds 变成已认证操作。


时钟与坐标补充：本地 user namespace root 不等于全局 UID 0 的授权主体，已加入实际拒绝对照；租期已转换 time namespace 的启动时钟偏移。非零单调偏移下 fanotify 与 BPF 的时间关联仍未适配，不能将租期修正扩大成完整 time namespace 支持。
