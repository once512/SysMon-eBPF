# 当前能力与下一步

更新于 2026-10-18。逐请求权限审计结果见 [最新验证](VALIDATION_PERMISSION_AUDIT_2026_10_18.md)，诊断隔离进展见 [本轮验证记录](VALIDATION_DIAGNOSTIC_2026_10_18.md)，目标授权及此前验证见 [授权与审计记录](VALIDATION_SCOPED_2026_10_18.md)，总体方向及历史决策保留在 [DESIGN](../DESIGN.md)。

目前已有一个主服务、BPF/fanotify 两个资源对象、独立降权分析器和短时管理工具；配置和活动 revision 统一。文件修改例外已能按执行 inode、EUID、目标和文件检查点声明，审计 stdout 使用有界队列，停止时先关闭权限组再输出统计。

## 本轮已收紧诊断 I/O 边界

服务期 stderr（含 libbpf 日志）现在使用独立有界队列：256 条、256 KiB、每行最多 4096 字节，FIFO 满时丢弃新行，超长行整行丢弃。所有后端的 status 提供 diagnostic_* 计数；stdout 审计与 stderr 的预算、线程和错误状态互相独立。

已经验证启动前填满 stderr、失败重载洪流、周期报告、恢复/断开、状态查询及不排空管道的授权退出。普通文件底层存储卡住仍可能影响输出线程 join；fanotify-only 的最终 stdout 统计仍是权限组关闭后的同步输出。具体契约见 [审计/诊断出口](AUDIT_OUTPUT.md)。

## 本轮已补齐逐请求裁决审计

--audit-permissions 在成功写回权限回复后输出 fanotify_decision，保留接收时的原始 PID、对象身份、revision、请求号和单调时钟；静态/扫描裁决、容量、超时、分析错误和正常停止拒绝都覆盖。忙时或准备失败的重载不会改写旧请求版本。对象身份从固定目标缓存，不为审计增加逐请求路径解析或 /proc 查询。

BPF 和 fanotify 借用服务拥有的唯一 stdout 队列；开启权限审计时，fanotify-only 的 stdout 也是 JSONL，结束统计写 stderr。共享预算没有按种类预留，日志丢失仍需通过 audit_* 及内核统计观察。字段与实际边界见 [逐请求裁决审计](PERMISSION_AUDIT.md)。

## 下一步：临时真实诱饵的行为关联

- 先在独立临时目录验证真实诱饵的读取/写入、别名和重命名，明确 fanotify 打开/读取入口与 BPF 修改拒绝的关联；不能假定一次调用必然同时产生两种记录。
- 将备份、索引、合法授权修改和未授权破坏作为对照，固定期望的对象、操作、时间与原因，再评估行为规则；字节标记命中和单次读取本身不等于恶意。
- 关联线程/进程生命周期及命名空间时使用明确的身份合同；现有 fanotify 原始 PID 不能单独充当可信主体，也不能直接拼到 BPF 全局任务身份上。
- 首轮只采集和解释证据；误报控制、确认后的规则更新、隔离和恢复分别设计并独立验收。不要让自动响应先于可信证据链。

## 补齐授权的信任与会话语义

执行 inode/EUID 匹配没有认证动态库、插件、解释器承载代码、环境和运行时完整性。当前 UID 是内核全局坐标；容器内 UID、程序部署和可信发布边界仍应单独设计。

研究内容/加载链认证时，先确定信任根、升级/回滚和撤销流程，再选择现成机制，避免自行发明签名体系。保险箱还需要读访问授权、期限、临时解锁及明确的锁定语义；现有共享可写映射、已复制内容和在途 I/O 不能靠删除一条 Map 规则追回。会话验收应明确哪些新访问被拒绝、已有能力如何处理。

## 建立可验证的行为与响应闭环

凭证基线异常目前属于审计线索，合成不一致测试不是已识别真实提权攻击。分析器的 BLOCK 字节规则也是实验机制。真实诱饵、行为关联、可信误报控制、确认后的拒绝/隔离和恢复流程尚未完成。

建议先用临时真实诱饵验证事件身份、操作、时间和原因的关联，再验证备份/索引等合法程序与破坏行为的区别。fanotify 已提供可选逐请求裁决及原因，下一步需验证真实诱饵和跨事件关联，不能将这些记录直接当作已确认攻击。响应优先更新拒绝规则，再考虑受控进程/cgroup 隔离；停止进程不能回滚此前写入。

## 按明确环境扩展覆盖

已有普通 FD、硬链接/重命名、部分 mmap/mprotect、私有 bind/tmpfs 和 PID namespace 专题。真实内核权限队列溢出、更多异步 I/O/文件系统专用路径、overlay/NFS/FUSE、完整容器和真实 PID 复用仍未据此认定覆盖。

一次只扩展一类入口或环境，保留独立实例、失败回滚和资源回收证据；不要为暂未确定的部署环境先增加历史协议/配置兼容层。资源对象继续按职责组合，内核侧保留 C/Map 模型，避免为了类数量而建立继承树。

## 临时诱饵证据阶段进展（2026-10-18）

已完成 [11 个受控操作的 open/access 实验](DECOY_EVIDENCE.md)，覆盖读取、授权写入、已有 FD、未授权修改和在线撤销授权；测试纳入权限专题 runner。角色仅为测试声明，尚无恶意识别或自动隔离。下一轮推进真实备份/索引负载、别名和路径变化，以及可信身份关联。

后续已完成 [完整读取/备份与路径变化实验](DECOY_EVIDENCE.md)：两种模式各四个文件工作负载，核对完整字节与摘要；覆盖硬链接、符号链接、授权改名和原路径不同 inode 替换。open/access 分别为 10/40 条正常 allow，旧 inode 各两次写入拒绝。下一步重点是进程/线程生命周期身份合同、并发与 namespace 边界；完整第三方备份和目录爬取仍未覆盖。
