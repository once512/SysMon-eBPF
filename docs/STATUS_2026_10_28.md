# 当前目标进度（2026-10-28）

目前是可运行的集成安全原型，机制和管理员使用流程继续完善；尚不是生产完成版或通用恶意识别引擎。用户态仍为GNU++17，BPF基于本机6.12内核，没有新增第二套内核授权底座。[历史规划与追加记录](../DESIGN.md)保留原始判断，本页描述本轮最终状态。

## 本轮交付

- [挂载归属](MOUNT_IDENTITY.md)：提供程序进度与实际挂载分开，attached/covered/moved/detached/unknown采样；不把进程存活当作挂载仍可见。root挂载路径拒绝用户可控制/可写祖先及FUSE祖先；公开视图仍存在上述覆盖缺口。
- [保险箱操作](VAULT_ADMIN.md)：secmon-vaultctl沿用root策略文件和既有Map；明确拒绝可恢复原始字节，丢失回复不冒充未激活。不会续期旧会话，拒绝修改会续期无关writer-lease的配置。
- [服务部署](SYSTEMD.md)：可选READY/STOPPING通知、生成并随文档交付服务模板；没有安装/启用系统单元或真实开机验收。
- [读取者恢复](READER_RECOVERY.md)：指定通信/格式/代理资源失败保留BPF及原group，确认拒绝/未确认分开计数。只有故障前即时allow且空闲时可按原代际显式恢复；普通重载不会悄悄恢复，也不能先改deny再绕过限制。离线期间独立vault关闭已验证。
- 完整/核心运行安装集合为6/5个程序；安装后从/运行组合视图、降权分析、响应、停止和核心Vim保险箱流程。管理协议为同包v11/528字节，提供协议v2/32字节；主服务和管理工具须一起更新。

没有把本轮扩展称为自动重挂载、加密保险箱、透明兼容全部编辑器或通用反勒索。当前已实现能力继续共用原有对象身份、策略Map、绝对时钟和root管理通道。

## 下一阶段顺序

1. 收敛公开视图的挂载干扰：本轮已复现UID65534经系统特权助手覆盖allow-other视图；检测covered不等于阻止覆盖。先定义挂载/卸载授权或部署隔离，保持普通用户诱饵修改触发，避免仅靠修改DAC绕过原检查范围。
2. 补齐资源限制/调度等进程干扰入口：task_setrlimit有实际目标task，可评估复用TASK_STORAGE及guard_task；当前故障注入实验证明该缺口存在。不得将信号/ptrace防护扩称完整自保护。
3. 受控提供程序恢复与拒绝/分析门恢复：需要共同证明挂载、对象和策略就绪；不能为恢复方便释放未知deny请求、卸载未知挂载或误认同路径新inode。
4. 最终用户授权与更多真实应用的保险箱流程；继续复用现有Map，不先新建授权底座。Vim本轮只验证明确的原地保存profile。
5. 可信恶意提权/勒索判据与独立误报证据，区分明确canary违规、基础观察和真实攻击分类。

只按新增功能与故障路径做定向验收；没有未解问题时不重复堆叠长负载。测试事实与原始产物见[本轮最终验收](VALIDATION_PROGRESS_2026_10_28.md)。
