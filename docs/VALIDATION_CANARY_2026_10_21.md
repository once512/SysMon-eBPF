# 2026-10-21 显式诱饵响应验收

功能提交：`6c0ed7c`。目标机器为 x86_64 Linux 6.12.0-211.61.1.el10_2，BTF 与 BPF LSM 已启用，GNU++17/libbpf/clang 本机构建。本轮交付真实诱饵的显式修改违规响应，范围见 [功能合同](CANARY_RESPONSE.md)；不交付虚拟诱饵或通用恶意分类。

## 实现及原规划关系

- 真实 canary 被修改时，在同次 BPF 钩子中发布有限期的 TGID 响应并拒绝该操作。后续受检普通文件修改及 fork/clone/exec 拒绝；普通读取、其他进程和普通保护拒绝不触发。
- 复用已有 inode 固定、不可变候选 Map、root 重载和 pidfs 身份。普通 revision 不解除/续期，更高响应 epoch 显式解除，期限由内核全局启动时钟执行。
- 新增4096项有界HASH，保留活跃状态，不以LRU淘汰。表满时原诱饵操作仍拒绝，响应创建失败单独审计和计数。
- 管理v7/432字节、BPF事件ABI7；主程序和嵌入对象同包构建。内层337项/368字节，原336个文件主体/目标容量不缩减。
- 联合测试发现并处理 vault/permission 订阅同 inode 的读取冲突：启动、别名重载、新目标切换均在候选阶段拒绝，保留旧策略，不隐式授权服务读取保险箱。固定 fanotify 对象先于 BPF 准备；加载/挂载仍不是所有钩子的全局原子启用。

相对原规划，这是具体部署假设下的首个在线响应闭环，未转向另一套底层文件基建。虚拟诱饵、可信恶意判定、fanotify 等待中的联合规则、真正挂起及完整隔离恢复仍在后续范围。

## 专题验证

五个新增特权专题：

| 专题 | 主要断言 |
| --- | --- |
| canary-response | 既有 FD、两线程、主线程先退出、普通拒绝反例、读取/私有映射、到期、epoch解除、回滚、别名冲突；暂停用户态仍触发和到期 |
| canary-capacity | 4096项表满不淘汰/续期；失败显式报告；释放容量后可触发；最后线程清理；200个真实进程生命周期及双线程并发触发 |
| canary-backpressure | 暂停消费者后真实拒绝10000次；实际耗尽ring buffer，响应期限不变，fork仍拒绝 |
| canary-namespace | 双PID namespace内均为PID1的进程彼此隔离；服务/客户端分别+3600/-60秒时，外部全局时钟验证真实到期 |
| canary-layers | sha256sum/cp/tar正常备份不触发；响应覆盖writer/vault写例外；fanotify中既已通过LSM的打开可完成，其后普通写入拒绝；vault/fanotify冲突拒绝和旧状态保留 |

既有共享可写映射的真实字节修改仍成功，这是明确验证的限制。权限检查已经通过的在途打开不会被事后撤销；没有将其记录为完整进程冻结或全部I/O封锁。
