# 内容分析事件读取隔离（2026-10-26）

在[静态读取者隔离](STATIC_EVENT_READER.md)上扩展内容分析模式。所有权限门均使用有界读取子进程；主队列只持有本地eventfd代理，主进程不再获取、查询或关闭正常权限事件的真实文件FD。

## 所有权与派发

读取者只保留管理通道、fanotify group，以及分析模式专用的分析器发送端（FD 3/4/5）；其他继承FD关闭。降权扫描器仍不持有group或BPF引用，启动握手、pidfd终止、单个在途请求与分析协议ABI不变。它不是完整沙箱。

主进程在已交付队列中选择请求，把不可复用的事件序号、原始FD令牌和分析请求号作为派发命令。读取者核对持有表，再用SCM_RIGHTS将真实文件直接发给扫描器；不经过主进程FD表。主进程登记在途请求后独立执行超时、版本与回退。读取者不读取扫描器结果，也不裁决。

读取者派发使用非阻塞sendmsg。发送失败会报告同一请求号的派发错误，由主进程按分析器错误回退并停止分析器；已超时/离线的旧错误不会二次回复或重复计数。清理命令与派发共用FIFO，当前最多4099条（4097个文件清理、一个在途派发及后续新增的一个进度探测）；真实文件仍最多4097个，全服务读取者槽仍最多16个。

扫描器回复及Ready使用无附件接收：不给recvmsg提供控制缓冲区，出现SCM_RIGHTS即以MSG_CTRUNC拒绝，不在主进程安装可读文件FD，也不调用close触发该文件的flush。事件原始引用仍由读取者持有，随后按错误回退/清理协议释放。该约束用于本协议事件文件的异常回复，不承诺任意恶意后端或任意文件系统内核回收都具有时限。

## 故障边界

读取者卡在FUSE事件创建、属性或关闭时，仍可能阻塞同group的新事件及尚未执行的分析派发；主队列已有请求照常超时。扫描器卡在新鲜fstat、pread或文件清理时，主进程可超时并定向终止它。超过期限后分析器保持离线，后续请求走既定错误回退，不自动重启。

pending与期限从主队列接收开始，不是原始系统调用的端到端期限。尚未交付的事件可能在关闭group时由内核释放，不能为其补造主进程裁决审计。停止会有界终止读取者，然后关闭group、停止扫描器；不可中断D状态仍可能延迟最后引用释放。配置源、启动及其他VFS等待边界未因此全部解决。

## 验证方法

```bash
sudo python3 -B tests/run_privileged.py --only fanotify-analysis analysis-faults virtual-analysis-reader requester-pidfd
```

新专题交叉独立/联合服务、legacy/pidfd与三种暂停位置：读取者获取事件、真实扫描器处理已传入文件、故障分析器回传多余文件FD。检查旧请求期限或错误回退、主体与审计原因、状态查询及暂停期间停止。独立实例通过/proc核对主进程仅保留目标O_PATH定位引用，不持有可读事件文件；联合实例的自保护拒绝该检查，保留自保护并以行为结果验证，不降低策略绕过检查。
